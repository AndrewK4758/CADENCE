# `/cadence-sync-jira` — script contracts: shared libraries

Bounded context: Tracker projection / Jira Server-DC adapter (BTG-075, BTG-247).
Boundary invariant: matches its siblings
`.agents/skills/cadence-sync-jira/jira-server-scripts.md` and the other `jira-server-scripts-*.md`
parts — the repository (`metadata.yaml` + `problem.md`) is the source of truth; Jira is the
projection layer, and every script communicates on exactly three channels (stdout `key=value`,
stderr `syncjs.*`, exit code).

**This file is a further part of one unified index, not another independent index.** It was split off by BTG-247, when
the primary file stood at 399 lines against a re-derived headroom threshold and the remaining shared-library
contract entries (`jira-rest.sh`, `jira-meta.sh`, `jira-link-lib.sh`, `jira-link-targets.sh`,
`jira-ac-lib.sh`, `jira-epic-lib.sh`, and `jira-lib.sh`) had nowhere to land in place. The record is
**split, never truncated** — the same pillar-tension resolution BTG-102, BTG-105, BTG-168, and
BTG-173 already applied here. The seam is "shared library, not an operation entry point" — every
entry below is sourced by at least one operation script and is never invoked on its own.

`btg-075-script-contract.test.sh`'s `js_index_view` merges every `jira-server-scripts-*.md` into the
primary before each lookup, so a split cannot hide a missing contract entry.

### jira-rest.sh

| Field | Value |
|---|---|
| **Operation/step** | Shared library, transport half — **sourced by `jira-lib.sh`**, never on its own and never invoked |
| **What it does** | Resolves the base URL and PAT through the config's `env` block (so a rebound variable name is honored), then issues every Jira REST v2 call: `js_rest` for JSON exchanges and `js_rest_download` for binary bodies, which `curl` writes directly to a file because command substitution would drop NUL bytes. It also owns `js_build_body <dest> <syncjs.condition> <subject> <jq-arg>...`, the **single** builder through which every request body in this skill is staged (BTG-084): it verifies BOTH questions the wire needs answered — did `jq` exit 0, and did it produce content — returns 0 built / 1 not built, and on 1 emits exactly ONE `syncjs.*_body_unbuildable` line and leaves the caller to decide skip-vs-halt without reporting again. `curl`'s own `-sS` diagnostic is captured into `JS_TRANSPORT_ERROR` so an unreachable transport can indicate whether the fault was DNS, TLS, or a proxy |
| **Inputs** | The `env` block of the config sidecar, and the environment variables it names |
| **Outputs (stdout)** | None — it sets `JS_HTTP_STATUS` / `JS_HTTP_BODY` / `JS_TRANSPORT_ERROR` for its caller |
| **Exit codes** | Returns (never exits): `0` on a completed exchange regardless of HTTP status, `3` when the exchange could not occur, `4` when the transport env cannot be resolved |
| **Re-run (idempotency)** | Pure transport with no state of its own; re-sourcing and re-calling is inherently convergent |

### jira-meta.sh

| Field | Value |
|---|---|
| **Operation/step** | Shared library, owned-data half — **sourced by `jira-lib.sh`**, never on its own and never invoked |
| **What it does** | Owns the `metadata.yaml` reader, and nothing else: `js_metadata_path` (`specs/` then `archive/`), `js_metadata_load` (a `python3` **stdlib** parser for the YAML subset these files use, which HALTS `syncjs.metadata.degenerate` on a degenerate parse rather than letting a caller no-op a projection), and `js_metadata_get`. It READS owned data and never writes it (AC-6). Four functions that previously lived here were relocated under the 400-line ceiling and are documented under their new homes: `js_metadata_list_signals` → `jira-link-signals.sh` (BTG-247, relocated again from `jira-link-targets.sh`), `js_ac_section` / `js_ac_items` → `jira-ac-lib.sh` (BTG-111 DEC-006 / DEC-019), `js_metadata_list` → `jira-meta-list.sh` (BTG-114 DEC-004) |
| **Grammar (the accepted YAML subset)** | The parser is a SUBSET reader, not a full spec-compliant parser, so `yaml.safe_load` accepting a file is not evidence that the sync can read it — that mismatch IS PROD_CADENCE-013. **Accepted:** block sequences; INLINE (flow) sequences `["A", "B"]` on one line, the form `/cadence-elicit` writes (DEC-043); one level of map nesting; the quote-DOUBLING escape (`''`); **a quoted scalar WRAPPED across physical lines**, folded on exactly one space per break in all three value positions (`k: "…"`, `- "…"`, `- k: "…"`) so this reader and a spec-compliant parser agree on the value (BTG-111 DEC-001); and, in a DOUBLE-quoted scalar, a **BACKSLASH escape** that consumes the next character — `\"`/`\\`/`\n`/`\t`/`\r`/`\0`/`\a`/`\b`/`\f`/`\v`/`\e` translate, while anything else falls through literally (BTG-114 G3; a SINGLE-quoted backslash remains literal, G2). **Refused, each naming the file, the OPENING line, and the last key read rather than being half-read:** the NUMERIC escapes `\x`/`\u`/`\U` (BTG-114 G4, never guessed); a flow sequence spanning lines; a **block scalar** (`\|`, `>`) in a mapping value; anchors/aliases; multi-document streams; map nesting past one level; a wrapped UNQUOTED scalar; and text after a closed quoted scalar, on **every** line and not only a folded one (BTG-111 DEC-008 / DEC-018 / DEC-020; BTG-114 drops the former FOLDED-only gate, closing member 7 — a value like `archive/PI-060`'s escaped-quote title used to be exempted from this same check for an unrelated reason that no longer holds). The canonical statement for AUTHORS is the note at the top of `specs/TEMPLATE/metadata.yaml`; this row is its script-side counterpart and the two move together |
| **Inputs** | `CADENCE_REPO_ROOT` (optional); `specs/<id>/metadata.yaml` or `archive/<id>/metadata.yaml` |
| **Outputs (stdout)** | None — it sets `JS_METADATA_PATH` / `JS_METADATA_JSON` for its caller |
| **Exit codes** | `js_metadata_load` HALTS (exit `1`) on a degenerate parse; the other helpers return non-zero without exiting |
| **Re-run (idempotency)** | Read-only over repository state — no writes of any kind, so re-reading is inherently convergent |

### jira-link-lib.sh

| Field | Value |
|---|---|

| **What it does** | Owns the ordered (`precedes`) link machinery once, so the umbrella branch reuses it rather than re-deriving the inversion calibration: `js_ordered_type_discover` resolves the instance's ordering type at runtime by matching the `precedes` / `is preceded by` **phrasing** (this organization's live type is named `precedes ` — trailing space, id `10400` — so a name-matched projection matches no stored link and has its POST rejected), preferring the configured id among the phrasing matches |

| **Re-run (idempotency)** | Convergent by CHECK-THEN-ACT, not by abstention — the type discovery is one read per run and holds no state, while `js_link_create_verified` and `js_link_upsert_ordered` are exceptions that `POST` links and `DELETE` reversed ones. Each re-reads the pair first and returns `up-to-date` when the link is already stored in the right direction, so a re-run writes nothing; when it does write, it creates the replacement BEFORE removing the reversed link (DEC-029), so an interrupted heal leaves both links present and repairable rather than leaving the pair unlinked |

### jira-link-targets.sh

| Field | Value |
|---|---|
| **Operation/step** | Shared library, the link TARGETS computation — **sourced** by `jira-link.sh` alone (its only caller); never invoked as an entry point and runs nothing on load |
| **What it does** | Owns the entire "what are this ticket's link targets" concern: structured extraction from `metadata.yaml`, the flat comment-signal loop, and deduplication. Its primary addition over the block it replaced is a TYPE DISPATCH on each keyed `related_tickets:` sub-key's value — an **array** fans out to one row per element (a map's `.ticket`, or a bare non-empty string), each element inheriting its **sub-key's own declaring key** so the relation falls out of `link_slots()` with no coupling-specific rule (DEC-001); an **object**, any element that is neither of the readable forms, and any candidate that does not LOOK like a ticket reference — which is how a flow-style (inline) map or list reaches this step, as the reader has no flow-mapping parser — is REFUSED by name as `syncjs.link.related_tickets_value_shape_unrecognized` and counted, never dropped and never interpolated (DEC-002/DEC-004/DEC-015/DEC-016); **every other value** emits the exact row it emitted before, byte for byte, `null` included (DEC-005). A second, independent `jq` pass enumerates what the first declined, so a refusal is DESCRIBED — sub-key, position, shape, value truncated to 120 characters — rather than inferred from a count mismatch. Its second addition is a single POST-ASSEMBLY VALIDATION CHOKEPOINT, between the flat loop and deduplication, through which EVERY arm's rows pass — the keyed extraction, the four top-level ordering keys, and the flat comment-signal loop alike: a row must be exactly `<declaring-key> <target>` with a reference-shaped target, and anything else is reported under the SAME condition name and counted, then dropped BEFORE deduplication can truncate it or `jira-link.sh` can interpolate it. That is why "what counts as a ticket reference" has a single authoritative answer here that any future arm inherits, rather than each arm carrying its own copy (BTG-108 DEC-008). "Reference-shaped" is an ALLOWLIST — letters, digits, `_`, and `-` — replacing a denylist that admitted `../../etc` and `CTS-61/62` straight into the path segment unencoded (BTG-108 DEC-001), and `structural` is DERIVED from it so the two cannot disagree (DEC-002). The dedupe's arity guard is `NF == 2`, not `NF >= 2`: once the chokepoint holds, a wider row is unreachable, which is why the guard stays — it asserts that any future upstream change re-opening PROD_CADENCE-011 fails loudly instead of silently truncating (BTG-108 DEC-006). It is READ-ONLY: no REST call, no file write, and it never writes `metadata.yaml` (AC-6). It landed here by RELOCATION under the 400-line DX ceiling on the DEC-057 / DEC-060 precedent (`jira-link.sh` measured 395 against a gate that fails at 400), and the relocation is TEXTUAL — same code, same variable names, same reports — making behavior-preservation on the flat path provable from the diff |
| **Also owns (relocated here)** | `js_metadata_list_signals <top-level-key>` — the RAW-comment reader for `related_tickets:`, emitting one `<value>\t<signal>` line per list item where the signal is the item's TRAILING COMMENT plus any comment-only CONTINUATION lines beneath it, with whitespace runs COLLAPSED so a phrase straddling a line break still matches every `js_relation_from_signal` pattern (DEC-032). It exists because the structured reader drops comments and this repository's relations are stated ONLY there. It moved from `jira-meta.sh` under the 400-line ceiling (BTG-111 DEC-006) into this file, which was already its **sole** consumer, and moved again (BTG-247, same ceiling) into the co-located `jira-link-signals.sh`, which this file sources unconditionally — the move keeps caller and callee together without changing any call site. It carries the SAME continuation FOLD as `js_metadata_load` (BTG-111 DEC-022): a list item whose quote opens and does not close on its line absorbs following lines until it does, one space per break, so a wrapped item does not terminate the block read and drop subsequent declarations. **BTG-114 closed the block-scalar debt (G7):** a block scalar's continuation no longer ends the block read silently — the indicator itself is refused by name before the fold reaches its body. For a PLAIN quoted item it runs the SAME escape-aware `quoted()` scan as `js_metadata_load` (G2/G3/G4) and resolves the quote FIRST (G1), splitting the signal off the tail, so a `#` inside a value is never a false comment boundary, and refuses a tab (G6) or any non-comment text after the close (G5) by name. A closure it still cannot resolve on a MAP-shaped item — a value escaping a quote by DOUBLING it (`''`/`""`), or a `- key: "..."` item whose quoted value wraps — makes it emit NOTHING, report `syncjs.link.related_tickets_value_shape_unrecognized`, and return **1**, which its caller counts as a refusal (BTG-111 DEC-023, narrowed by BTG-114 to map-shaped items only — a PLAIN item's doubled escape is now parsed). Thus the three readers of one file never disagree about a value: this one either agrees with the loaders or refuses aloud. `specs/TEMPLATE/metadata.yaml`'s authoring note states what this reader accepts and refuses |
| **Inputs** | Its caller's variables — `$JS_METADATA_JSON` (the parsed `metadata.yaml`) and `$JS_METADATA_PATH` (the raw file, which `js_metadata_list_signals` reads directly for trailing-comment signals). No arguments, no config, no instance read |
| **Outputs (stdout)** | None — it sets `JS_LINK_TARGETS` (the deduplicated `<declaring-key> <target>` rows, newline-separated, possibly empty) and `JS_LINK_TARGETS_UNPARSEABLE` (a non-negative count) for its caller, which seeds them into `TARGETS` and `REJECTED`. It is called DIRECTLY, never inside `$( )`: a subshell would discard the counter and the caller would report a clean run over a declaration this step refused — the same reason `js_ordered_type_discover` sets `JS_ORDERED_NAME` instead of printing it |
| **Exit codes** | Returns `0` always (never exits): an unreadable declaration is a reported, counted refusal, not a failure — linking is best-effort and this step never halts the ticket. A `jq` failure leaves the rows empty rather than aborting the caller |
| **Re-run (idempotency)** | Pure: it reads owned data and writes nothing, holding no state and converging trivially — the same `metadata.yaml` yields the same rows and count on every run. That is why the defect it fixed was permanent: a shape it could not read failed identically forever without self-healing |

### jira-epic-lib.sh

| Field | Value |
|---|---|
| **Operation/step** | Shared library, `type: epic` fork — **sourced** by `jira-write-issue.sh` and `jira-epic.sh` (the two scripts that need to know which branch an epic takes); never invoked as an entry point and runs nothing on load |
| **What it does** | Owns the BTG-036 fork once. `js_epic_link_field` discovers the Epic Link custom field's id by EXACT name (plugin-provided, per-instance; zero matches and more than one both resolve to "unreadable", never to a guess). `js_epic_branch <key>` reads the ticket's own **live** Epic Link and returns the branch: empty ⇒ `single-level`, populated ⇒ `umbrella` with `JS_EPIC_E` = the top-level epic. `js_umbrella_summary <title>` computes `[UMBRELLA] {title}` by strip-then-prepend, keeping the prefix single by construction. Everything it owns is discovery — **reads only, with exactly one exception**: `js_epic_child_associate` owns the child branch's single Epic Link `PUT`, staging its body and REFUSING the write when the scratch file or `jq` build fails rather than issuing a bodyless `PUT` that a permissive server accepts while reporting success. EXIT`** (BTG-079 AC-3): the shell keeps only ONE EXIT trap per process, so a trap armed inside a SOURCED library function REPLACES its caller's, causing the caller to silently lose its armed cleanup (`jira-write-issue.sh`'s `trap js_cleanup EXIT`). Instead, it unlinks its own scratch file at each of its exits. It never writes `metadata.yaml`, and neither does anything else here (AC-6) |
| **Inputs** | `link_relations.epic_link_field_name` via `jira-lib.sh`; `GET /rest/api/2/field` and `GET /rest/api/2/issue/{key}?fields={epicLinkId}` from the instance |
| **Outputs (stdout)** | Discovery sets `JS_EPIC_LINK_FIELD` / `JS_EPIC_BRANCH` / `JS_EPIC_E` for its caller (`js_umbrella_summary` prints its one value). Its **three exiting functions** additionally write their caller's payload, which is why those values are declared here too: step 4's five keys `issue_key=<KEY>`, `jira_url=<url>`, `estimate_result=none\|unprojectable\|cosent\|original-only\|field-unsupported\|followup-written`, `epic_branch=umbrella\|single-level`, `ac_result=skipped-epic`, and `js_epic_child_associate`'s `epic_result=associated\|rejected`. `estimate_result` carries **all six** of `jira-write-issue.sh`'s values, not just `none`: `js_epic_write_plan`'s umbrella exit emits the literal `none`, while `js_epic_ac_skip_exit` PASSES ITS CALLER'S VALUE THROUGH as `"$4"` |

A non-zero return is **never** a branch — the caller reports and refuses to mutate, because promoting on a failed read writes the state Jira forbids. The two step-4 early exits (`js_epic_write_plan`'s umbrella branch, `js_epic_ac_skip_exit`) exit `0` after emitting step 4's payload, and `js_epic_child_associate` exits `0` on every outcome including a refusal or rejection (DEC-033) |

That converges by OVERWRITE, because the value is derived from the parent each time |
