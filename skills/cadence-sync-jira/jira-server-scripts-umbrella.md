# `/cadence-sync-jira` — script contracts: the umbrella replacement

Bounded context: Tracker projection / Jira Server-DC adapter (BTG-075, BTG-105).
Boundary invariant: matches its sibling
`.agents/skills/cadence-sync-jira/jira-server-scripts.md` — the repository (`metadata.yaml` +
`problem.md`) is the source of truth; Jira is the projection layer, and every script communicates on
exactly three channels (stdout `key=value`, stderr `syncjs.*`, exit code).

**This file is the second part of one unified index, not a second independent index.** It was split off by BTG-105, whose
umbrella replacement flow added a module and expanded `jira-epic.sh`'s entry, pushing the
single file past the 400-line Agentic DX ceiling. The record is **split, never truncated** — the same
pillar-tension resolution BTG-102 applied to the condition catalogue (C-3: Operability outranks DX on
*content*; DX is served by file placement instead). The seam is the umbrella replacement flow: the script
that owns it and the module that performs its writes.

Its reported conditions are catalogued in
`.agents/skills/cadence-sync-jira/jira-server-conditions-umbrella.md`.

### jira-epic.sh

| Field | Value |
|---|---|
| **Operation/step** | Best-effort — project the Epic relationship |
| **What it does** | Two branches, forked SOLELY on the ticket's own **live** Epic Link (BTG-036) — never on whether it declares children. **Empty ⇒ single-level Epic:** zero links and zero writes here; each child sets its own Epic Link when it syncs. **Populated (= `E`) ⇒ umbrella:** Jira Server/DC forbids an Epic from carrying an Epic Link, so the ticket is not an Epic at all — and the umbrella carries one, which is why it must be a plain issue. **BTG-105 replaced the in-place re-type with a REPLACEMENT flow** (writers in `.agents/skills/cadence-sync-jira/jira-umbrella-lib.sh`): the branch resolves its mode from the repo-owned `umbrella_epic_url` scalar, **creates** a fresh issue `U` already at `umbrella.issue_type` (born at that type, so no existing issue's workflow is stranded), sets `U`'s Epic Link to `E` with a mandatory read-back, moves each child's ordered `is preceded by` link onto `U` and **retires the stale one from the original — create before delete, never leaving a pair unlinked**, then **closes** the original by a transition resolved from `status_workflow_map[<its LIVE type>]["archived"]` — and when that close does **not** land it reports that on the machine channel as `epic_result=umbrella-unclosed`, because `jira_url` then stays on the superseded original and steps 1–8 keep writing to it. **No `issuetype` and no `summary` write is issued against any pre-existing issue on this path.** The child Epic Link write is **byte-unchanged**: each child's Epic Link ← `E`, the **top-level** epic, pointing *past* the umbrella, which makes the projection depth-uniform and keeps the board shape unchanged. The entire child set is resolved BEFORE the first write (`syncjs.umbrella.child_unresolved`), so no child is left written while its siblings are not; a partly-applied set reports `syncjs.umbrella.partial` **and** carries that partiality on the machine-readable channel as `epic_result=umbrella-partial` — the orchestrator parses the payload, never stderr, so a flat `umbrella` beside a partial condition would read as a complete projection — and it **defers the close**, so an issue is never retired while a child is stranded or dual-linked. A skipped ordered link (when the instance's link types were unreadable) counts as unapplied like any other. A child already pointing at a *different* Epic is resolved by the run-mode predicate (`syncjs.umbrella.child_epic_link_conflict`) — headless overwrites, interactive leaves it untouched, with interactive as the fail-safe default. **Child:** sets this issue's own Epic Link to its `decomposed_from` parent, discovering the field id by name and leaving an already-correct value untouched |
| **Inputs** | `--ticket <id>`, `--issue-key <KEY>`. Reads `type` / `title` / `decomposed_into` / `decomposed_from` / `umbrella_epic_url` / the parent's `jira_url` from `metadata.yaml`, and `link_relations.epic_link_field_name`, `umbrella.issue_type`, `status_workflow_map` (including `global_transitions`), and `run_mode.headless_env` from the config sidecar, plus the run-mode env signal itself |
| **Outputs (stdout)** | `epic_result=umbrella\|umbrella-partial\|umbrella-unclosed\|associated\|at-target\|none\|rejected`; `epic_children_linked=<n>` on the umbrella branch; `umbrella_epic_url=<browse url>` as soon as the replacement exists — **even on a refusal that leaves it unlinked**, because the issue EXISTS and a dropped binding would mint a second replacement next run; and `jira_url=<browse url of the replacement>` **only** on full completion, which keeps a partial run convergent. The orchestrator's `jira_url` extraction is last-one-wins, so this overrides step 4's with no orchestrator change. **`umbrella-unclosed`** is the close step's analogue of `umbrella-partial`: the child set was complete, but the original could not be closed, so `jira_url` still names the **superseded** original and steps 1–8 keep writing to it — a **split** projection that a flat `umbrella` would misreport as complete |
| **Exit codes** | `0` for **every** epic/umbrella outcome, including every failure inside the branch — a best-effort step halts its BRANCH, not the ticket, reporting its condition and emitting `epic_result=rejected` rather than exiting non-zero, which the orchestrator would treat as breakage (DEC-033). `1` only from the shared library, on a degenerate `metadata.yaml` for THIS ticket (a degenerate CHILD `metadata.yaml` is caught by the pre-write validation pass, which runs in a subshell so its halt cannot escape). `2` usage; `4` config HALT. Never `3`: an unreachable transport is reported and the branch still exits `0` |
| **Re-run (idempotency)** | Set-to-desired with a read first: a child already pointing at the right Epic is left untouched, so a re-run re-asserts nothing and creates nothing. **At most one replacement umbrella issue per ticket, ever**, decided from the repo-owned `umbrella_epic_url` and **never** by searching the tracker (`CADENCE_ORG.md` §9). **Every config HALT (`exit 4`) precedes the first mutation** — including ordered-link type discovery, which is a *read* that halts on an absent binding: a halt standing *after* the object-creating `POST` and before this script RETURNS would still mint a fresh orphan on a re-run, because since BTG-125 the orchestrator records `umbrella_epic_url` the moment this script returns, not before — so a halt inside it, however late, is not yet recorded. A recorded replacement for which the instance answers 404 is a contradiction: `syncjs.umbrella.binding_contradicted` — fail loud, create nothing. A recorded replacement that exists but carries **no** Epic Link is **converged, not assumed**: the same read that proves existence re-asserts the link, and a refusal blocks the close and the `jira_url` re-point. Once `jira_url` also names the replacement, the branch is *settled*: it converges the ordering links only, so a later-added child still receives one, and never closes the live umbrella |

### jira-umbrella-lib.sh

| Field | Value |
|---|---|
| **Operation/step** | Shared library, the umbrella REPLACEMENT writers — **sourced** by `jira-epic.sh` (its sole caller today); never invoked as an entry point and runs nothing on load |
| **What it does** | Owns the five writers BTG-105 introduced when replacing the umbrella re-type with a create-and-close flow. `js_umbrella_mode` resolves the branch's mode — `replace` / `converge` / `settled` — from the **repo-owned** `umbrella_epic_url` scalar ALONE, never from a tracker read (`CADENCE_ORG.md` §9): deriving idempotency from mutable external state is what allows a human rename to mint a duplicate. `js_umbrella_issue_ensure` **creates** the replacement at `js_config_map umbrella issue_type` — the SAME config key the deleted re-type used, re-pointed from an update to a create, so the issue is **born** at that type and no existing issue's workflow is ever stranded — reading its key from the response's `.key` and never computing one; in `converge`/`settled` it first PROVES the recorded binding is real and treats a 404 as a **contradiction** (`syncjs.umbrella.binding_contradicted`: fail loud, create nothing), never as license to re-create. `js_umbrella_epic_link` sets the replacement's Epic Link to `E` in its own write carrying the discovered custom field **only** — no `issuetype` — with a mandatory read-back; it is called on both the create path and the `converge` path, because **existence is not lineage**: proving that the bound issue exists says nothing about whether it carries its Epic Link, and `epic_link_unset` leaves that exact state behind for the next run to inherit. In `settled`, the same shared arm still runs, but the comparison is **identical by construction** — `E` is `U`'s own live Epic Link, read from the same field of the same issue by `js_epic_branch` moments earlier — so no write is issued absent a **concurrent external mutation** landing between the two reads (`archive/BTG-105/decisions.md` DEC-025 Rationale). A refused re-assertion returns non-zero, so the caller closes nothing and re-points nothing. `js_umbrella_ordered_type` resolves the ordered link type from the instance (relocated whole from `jira-epic.sh` under that file's DX ceiling). `js_umbrella_stale_links` takes ONE snapshot of the original's issue links before the child loop, and `js_umbrella_ordered_retire` **discovers** each stale link's id from it — never computing one — matching in EITHER direction, and deletes it only AFTER the replacement link is verified (**create before delete**, so a child is never left unlinked; worst case dual-linked, which is reported and counted). `js_umbrella_original_close` retires the original via a transition resolved from `status_workflow_map[<its LIVE issue type>]["archived"]`, matched against the instance's offered set and falling back to the existing `global_transitions` id — **no walk and no guess**, because a collapsed transition set is where a walk wanders onto an ungoverned state — with a mandatory status read-back. It installs **no `trap ... EXIT`** (BTG-079 AC-3): the shell keeps only ONE EXIT trap per process, so a trap armed inside a SOURCED library function would REPLACE its caller's; each exit path unlinks its own scratch file instead. It never writes `metadata.yaml` (AC-6) |
| **Inputs** | `title` / `umbrella_epic_url` from the ticket's `metadata.yaml` via `jira-lib.sh`; `umbrella.issue_type`, `status_workflow_map` (including `global_transitions`), and `link_relations` from the config sidecar; `env.project_key`. From the instance: `POST /rest/api/2/issue`, `GET`/`PUT /rest/api/2/issue/{key}`, `GET /rest/api/2/issue/{key}?fields=issuelinks`, `DELETE /rest/api/2/issueLink/{id}`, `GET`/`POST /rest/api/2/issue/{key}/transitions` |
| **Outputs (stdout)** | **None of its own.** It sets `JS_UMB_MODE`, `JS_UMB_ISSUE`, `JS_UMB_T_READ`, `JS_UMB_T_LINKS`, `JS_UMB_RETIRE`, and `JS_UMB_CLOSE` for its caller, which owns the payload; its conditions go to stderr under the `syncjs.umbrella.*` prefix (`.agents/skills/cadence-sync-jira/jira-server-conditions-umbrella.md`) |
| **Exit codes** | Returns, never exits. `0` on a usable outcome, non-zero on a refusal — except `js_umbrella_original_close`, which **never** returns non-zero: the umbrella branch is best-effort and halts the BRANCH, never the ticket (DEC-033). `js_umbrella_issue_ensure` returns non-zero **with `JS_UMB_ISSUE` still set** on the `epic_link_unset` arm, because the issue EXISTS and its binding must be recorded regardless. A config HALT propagates as `4` |
| **Re-run (idempotency)** | Convergent by design and by REPO-OWNED state: `replace` creates at most one replacement per ticket ever; `converge` re-asserts the ordered links (the create reports up-to-date, preventing duplicates) and retries the retirement and close against freshly read state; `settled` converges the ordering links only, so a later-added child still receives one, and never closes the live umbrella. A dual-linked child, a deferred close, and an unset Epic Link all converge on the next run rather than compounding |
