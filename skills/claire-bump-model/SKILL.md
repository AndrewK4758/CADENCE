## Task

Bump one capability tier's concrete model identifier from `$from_model` to `$to_model` across every representation that names it, atomically in one invocation. The concrete model is AUTHORED in two places — the tier-resolution case arm in the runtime adapter under `ci-templates/scripts/adapters/*.sh`, and the concrete-model column of the corresponding tier row in `docs/agentic-sdlc/CLAIRE_ORG.md#model-tier-mapping` — and is PROPAGATED into the compiled agent frontmatter (`.claude/agents/*/AGENT.md` `model:` lines) by a recompile. The adapter is the machine source of record; the compiled tree is a build output that is regenerated by `claire-compile.sh`, never hand-edited (editing it directly is the exact anti-pattern a later recompile silently reverts).

The framework declares two capability tiers (Deep-reasoning, Fast-mechanical) in `CLAIRE_ORG.md#model-tier-mapping`. Each tier has one concrete-model identifier for the current runtime. This skill bumps the concrete identifier for one tier at a time — explicit `from` and `to` arguments keep tier boundaries visible and prevent silent cross-tier moves.

## Prerequisites

- Both `$from_model` and `$to_model` are required arguments. If either is missing, stop and tell the user the correct invocation: `/claire-bump-model <from-model> <to-model>`.
- Both arguments must follow the model-identifier convention recorded in `CLAIRE_ORG.md#model-tier-mapping` for your runtime. If either does not match the convention used in the mapping table, warn the user — naming conventions may evolve, but unexpected formats are likely typos. Proceed only if the user confirms.
- The Model Tier Mapping section must exist in `CLAIRE_ORG.md`. If absent (e.g., an adopter on an older fork), stop and warn the user before applying any edits.

## Steps

### 1. Validate arguments

Confirm both `$from_model` and `$to_model` are present and match the identifier convention in `CLAIRE_ORG.md#model-tier-mapping`.

If `$from` and `$to` belong to **different tiers** in the mapping table, **stop and refuse**. A cross-tier change is not a version bump; it is an architectural choice that affects agent behavior, capability, and cost. It warrants an intent issue and a spec, not this skill. Tell the user explicitly: this skill only bumps the concrete identifier within a single tier.

If `$to` is not yet listed in any tier (the usual case — it is a newly released model), look up `$from`'s tier and treat the bump as intra-tier: the adopter is updating that tier's concrete identifier. Only refuse when `$to` already appears in a *different* tier's cell, or when the runtime's naming convention makes the tier mismatch evident (see the Worked Example for the reference-instance heuristic).

### 2. Find all references

Two AUTHORED targets to locate before showing any diff. The compiled agent files (`.claude/agents/*/AGENT.md` `model:` lines) are DERIVED from the adapter, so they are NOT searched or edited here — a recompile regenerates them in Step 5.

**Adapter tier-resolution case arm(s):** locate the tier-resolution case arm in `ci-templates/scripts/adapters/*.sh` whose concrete-model literal reads `$from_model`. Tolerate an optional `<provider>/` prefix (some runtimes namespace the model id inside the literal), so match `$from_model` with or without a leading `<provider>/`.

```bash
grep -rn "$from_model" ci-templates/scripts/adapters/
```

**Tier mapping row:** locate the row in the `### Tier → Concrete Model` table inside `CLAIRE_ORG.md#model-tier-mapping` whose concrete-model column currently reads `$from_model`.

If neither target matches, stop and report: no adapter case arm or mapping row references `$from_model`. This is either a typo, a no-op (the bump already happened), or the framework's adapter and mapping were never on that model.

If exactly one of the two targets matches (mapping row matches but no adapter arm does, or vice versa), report the mismatch and ask the user whether to proceed with the partial set. Apply edits only if the user confirms the partial scope.

### 3. Show the user a diff (both targets)

For each matched adapter case arm, present:

```
<adapter file> (tier-resolution case arm, tier <tier-name>):
  - <from_model>
  + <to_model>
```

For the mapping row, present:

```
docs/agentic-sdlc/CLAIRE_ORG.md (Tier → Concrete Model, row <tier-name>):
  - <from_model>
  + <to_model>
```

List all targets that would change. Do NOT show or edit any compiled `.claude/agents` file — those are regenerated by the recompile in Step 5. Do not edit anything yet.

### 4. Confirm with the user

Ask explicitly: *"Apply M adapter case arm(s) + 1 mapping row, then recompile?"* (where M is the count of matched adapter case arms from step 2). Wait for confirmation before editing.

If the user declines, stop and report no changes were made.

### 5. Apply edits + recompile

For each matched adapter case arm, use the Edit tool to replace the concrete-model literal `$from_model` with `$to_model` (preserving any `<provider>/` prefix). The literal is unique within each adapter's tier-resolution function, so a single edit per arm is safe.

For `CLAIRE_ORG.md`, use the Edit tool to replace `$from_model` with `$to_model` in the matched concrete-model cell of the `### Tier → Concrete Model` table.

Then regenerate the compiled tree from the neutral source:

```bash
bash ci-templates/scripts/claire-compile.sh
```

Never hand-edit a compiled `.claude/agents` file to change the `model:` line — it is a build output, and a recompile is the only sanctioned way to propagate the new value into every agent's `model:` line.

### 6. Verify

Re-derive the compiled tree and confirm the propagation is complete across every representation:

```bash
bash ci-templates/scripts/claire-compile.sh --check
```

Confirm BOTH:

- A clean round-trip (every compiled agent `model:` line agrees with the adapter's fresh resolution).
- The mapping row's concrete-model cell now reads `$to_model`.

If the round-trip is NOT clean, the propagation was incomplete (`bump-model.reference_search.incomplete_representation_set`): halt and report which representation diverged, and tell the user to inspect `git diff` and roll back manually — do not attempt automatic recovery. This `--check` verification is the durable backstop that a future bump cannot silently repeat the c75bf3d drift (a mapping row / compiled file bumped without the adapter).

### 7. Report outcome

Tell the user:

- How many adapter case arms were edited (M) plus the mapping row (1), reported as "M adapter case arm(s) + 1 mapping row updated, compiled tree regenerated".
- Which adapter file(s) (with paths).
- That the compiled agent `model:` lines were regenerated by the recompile (not hand-edited) and the `--check` round-trip verified clean.
- That changes are not yet committed. The user should review the diff (`git diff ci-templates/scripts/adapters/ docs/agentic-sdlc/CLAIRE_ORG.md .claude/agents`) and commit per their normal workflow. Suggest a commit message form: `Bump <tier> tier from <from> to <to>`.
- That this skill does **not** touch:
  - The denylist model-string lists that guard neutral source (the vendor/primitive sweep patterns) — a one-time consistency edit, not part of the ongoing bump (the `--check` verify is the real backstop).
  - Documentation prose that mentions model identifiers (release notes, examples, capability discussions) — those often have surrounding context that needs human judgment.
  - CI configuration, external routing (Portkey, gateway), or other systems that may also reference the model.
  - Other tiers (e.g., if the other tier also has a release, run the skill again with that tier's `from`/`to`).

## Out of Scope

- **Documentation prose.** Model identifier references in prose (release notes, capability discussions, examples) often have surrounding context that needs adjustment. The skill does not touch them.
- **CI configuration.** If the framework's CI references a specific model elsewhere, this skill does not look there.
- **External routing.** Portkey routing, API endpoint mappings, model deployment configs — all live outside this repo.
- **Cross-tier changes.** Moving the concrete identifier for one tier into the cell of another tier is an architectural choice, not a model bump. The skill refuses cross-tier inputs.
- **Bulk multi-tier updates.** If both tiers need updating at once, run the skill once per tier. Bundling tiers in a single invocation would obscure which agents changed for which reason.

## Worked Example (Claude Code)

This repo dogfoods Claude Code. Concrete model identifiers in `CLAIRE_ORG.md#model-tier-mapping` follow the Claude convention `claude-{opus|sonnet|haiku}-N-M` (e.g., `claude-opus-4-7`, `claude-sonnet-4-6`).

### Cross-family refusal (Claude-specific instance of the cross-tier rule)

If `$from` is in one Claude family (e.g., `claude-opus-*`) and `$to` is in another (e.g., `claude-sonnet-*`), the skill refuses — under Claude Code, families map to tiers (Opus → Deep-reasoning, Sonnet → Fast-mechanical), so cross-family is cross-tier, which is a tier change rather than a model bump.

### Invocations

```
/claire-bump-model claude-opus-4-6 claude-opus-4-7
```

Bumps the Deep-reasoning tier's concrete identifier (and every agent on `claude-opus-4-6`) to `claude-opus-4-7`. The Fast-mechanical tier is not touched.

```
/claire-bump-model claude-sonnet-4-5 claude-sonnet-4-6
```

Bumps the Fast-mechanical tier's concrete identifier (and every agent on `claude-sonnet-4-5`) to `claude-sonnet-4-6`.

```
/claire-bump-model claude-opus-4-6 claude-sonnet-4-7
```

**Refused.** Cross-family = cross-tier under Claude Code. The skill stops and tells the user to file an intent issue for a tier change.
