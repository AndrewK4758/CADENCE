## Task

Perform intake triage on the issue designated by `$ticket_id`. Delegate the analytical evaluation to the `cadence-triage-agent` subagent (powered by automatic `local_semantic_embed` and `local-moe-hybrid` pre-discovery). Once the subagent completes, if the issue is classified as Medium or High tier and still contains unanswered template probes, offer to guide the requester through those probes interactively by invoking the `cadence-elicit` skill.

**Handoff mode.** The `/cadence-elicit` skill can call `/cadence-triage` programmatically to mint and initialize a decomposition child ticket (see step 4d of `cadence-elicit`). Whenever the call includes a handoff payload (carrying `parent_ticket_id` and `suppress_elicit_offer`), obey the handoff-specific branches in step 3 and step 5 below and return the structured payload defined under **## Handoff mode (decomposition children)**. Standard `/cadence-triage <id-or-description>` invocations omit that payload and execute the standard triage flow.

## Steps

0. **Automatic Local Discovery Pre-Pass (`local_semantic_embed` / `local-moe-hybrid`).** Prior to broad repository file reads or duplicate scanning (unless `--file-only` is active, which performs no classification or duplicate search), automatically invoke `local_semantic_embed` (`local-embed-cpu` on `:11434`, 0 MB VRAM) and/or the `local-moe-hybrid` discovery coprocessor (`gemma-4-26b-a4b` on `:11434`) to index and query `specs/`, `archive/`, `docs/agentic-sdlc/intent-insights.md`, `docs/agentic-sdlc/production-insights.md`, and relevant codebase symbols. 1. **Resolve the identifier-allocation binding** from `CADENCE_ORG.md#id-allocation-binding` (§10) alongside the bound issue tracker from `#tracker-binding` (§9 — resolve **vendor-neutrally**, never hardcoding any tracker product name). This skip remains auditable through the existing `originated_from_tracker:` attribute in `metadata.yaml`. **Do not invoke `--reserve`** on this branch — the identifier is already allocated, so no ledger number is consumed. Proceed straight to classification (steps 3+), without re-seeding.

      **"Do not overwrite" specifically means "never re-seed from the external tracker"** (BTG-327) — it does not block the triage-agent's own classification updates: the obligation in Outputs step 1 to draft or flag Acceptance Criteria (`cadence-triage-agent` Outputs step 1, including `triage.acs.placeholder_survived` prevention) still executes on this branch, replacing any template placeholders left behind by an earlier `--file-only` filing.

      - **Record the binding resolution** (resolved allocator + ticket id + binding source) **prior to contacting the tracker** — following the §9 record-before-contact precedent so the inbound seed-read is auditable before network I/O begins.
      - Resolve the bound tracker from `#tracker-binding` vendor-neutrally and fetch its issue summary **exactly once**.
      - Seed `problem.md`: map the tracker **summary → Problem Statement title**; map the **description body → Business Context, fenced as an inbound seed**. Keep the field mapping **minimal**. **Attachments** on a seed-read tracker issue **are** a permitted inbound content class — the bound tracker's Import operation downloads them into `specs/{id}/attachments/` and links each file from `problem.md` under Supporting Evidence (BTG-043 / OQ-1 → (a): a documented field-map extension rather than a charter expansion). **Do not map acceptance criteria inbound** — a dedicated future ticket governs inbound AC mapping content-class by content-class, as importing them here would exceed the single sanctioned inbound channel in ADR_CADENCE-0011 cl.2.
      - Write the required provenance markers: insert a `## Source: tracker seed-read $ticket_id (non-authoritative after triage)` section in `problem.md`, and record `originated_from_tracker: $ticket_id` plus `seed_read_at: <ISO-8601>` in `metadata.yaml`. This seed-read is **one-time and non-authoritative** — subsequent edits in the external tracker never flow back into the repository (AC-2).
      - **SUSPECTED UNPAIRED RESERVATION.** Whenever the seed-read yields a summary title but **an empty description body** (reported by the triage-agent as `idalloc.reserve.orphan_suspected`), recognize that pattern as the footprint of a reservation-created tracker stub — a `reserve` call supplies only a summary line. Surface this directly to the requester: cite the ticket id, explain clearly that the seeded stub will contain only a title, and **ASK** whether they want to paste a description now or continue with the title-only seed. Because this is a **HEURISTIC indicator rather than definitive proof** — a human operator can legitimately file a title-only issue — it **never refuses execution**, **never attempts auto-repair**, and never modifies the provenance-marker rules above. It **inspects no tracker field beyond what the seed-read already fetches**, adding **NO extra inbound flow** (**ADR_CADENCE-0011 cl.2** remains intact; a proactive orphan scan against the tracker *would* constitute an unsanctioned second inbound flow and is out of scope).
      - **When the tracker MCP is unreachable:** fall back by prompting the user to paste the issue description directly, and **write NO provenance markers** (omit the `## Source:` block and omit `originated_from_tracker`/`seed_read_at`). Because this fallback occurs at the *write* boundary, a subsequent retry can still perform a clean one-time seed-read (F4/DEC-011) — an unreachable fetch does not count as a completed seed-read.

Note that this is the **EXPLICIT INVERSE of §9's fail-loud rule** — an unbound *allocator* is **not** a configuration fault; it selects local sequence minting. When `$ticket_id` looks like a tracker key, you MAY read it from the repo's bound tracker **strictly for context**, recording **NO provenance markers** (no `## Source:` heading and no `metadata.yaml` provenance attributes). If the tracker cannot be reached, prompt the user to paste the description. Skip this sync if no files were written (handoff-mode duplicate return). **In handoff mode, do not sync the child ticket inside `/cadence-triage`** — `/cadence-elicit` governs the atomic all-or-nothing decomposition transaction and syncs each committed child in `cadence-elicit` step 7; syncing mid-handoff would risk projecting a child that a subsequent sibling failure rolls back.
   A full classification run (excluding `--file-only`) also produces a `Phase: Triage` record in `specs/{ticket-id}/decisions.md` — authored directly by `cadence-triage-agent` (see `cadence-triage-agent` Outputs step 3) rather than by this orchestrating skill.

4. **Present the triage summary** to the operator:
   - Assigned type, priority, and scope/tier
   - Affected codebase modules and files
   - Related or duplicate prior tickets discovered via `local_semantic_embed` / `local-moe-hybrid`
   - Recommended next lifecycle command
   - Verbatim `Acceptance Criteria:` status line (BTG-327) from `cadence-triage-agent` Outputs step 4 -- either `drafted N` or `no ACs derivable` with its stated reason -- making the AC disposition immediately visible without opening `problem.md`.

5. **Offer the interactive probe interview (Medium/High tier only).** Because `cadence-triage-agent` executes as an autonomous subagent and cannot converse with the human requester, the interview offer executes here in the main turn after the subagent completes:

   - **Handoff-mode gate (evaluated first):** when the invocation payload contains `suppress_elicit_offer: true`, **bypass this step completely** — print `"Created child <id> from decomposition of <parent_ticket_id>; elicit offer suppressed."` and return the handoff response object. This prevents newly minted decomposition children from recursively triggering `/cadence-elicit`.
   - Read the `tier:` attribute from `specs/$ticket_id/metadata.yaml`. Normalize by trimming surrounding whitespace and quotes and converting to lowercase.
   - Count the remaining unanswered probes in `problem.md`:
     ```bash
     grep -cF '_Answer:_ _(not yet answered)_' specs/$ticket_id/problem.md
     ```
   - **When the normalized tier is `medium` or `high` AND the unanswered probe count is > 0:** prompt the requester with the exact question — `"N probe(s) are unanswered. Walk through them now? (yes/no)"` (replacing `N` with the integer count).
     - On `yes` (case-insensitive): invoke the `cadence-elicit` skill for `$ticket_id` (equivalent to `/cadence-elicit $ticket_id`) within the current turn. Do not duplicate elicitation logic inside `cadence-triage` — `cadence-elicit` enforces the tier gate, idempotency check, verbatim recording rules, and 7-question cap.
     - On any other input (including `no` or an empty response): skip the interactive interview and leave the triage recommendation (`"Run /cadence-elicit $ticket_id"` later) intact.
   - **When the normalized tier is `trivial` or `low`, the unanswered count is 0, or `tier:` is absent/unrecognized:** do not offer the interview. This aligns with `cadence-elicit`'s tier gate in `docs/policies/change-tiers.md` and avoids offering an interview that `cadence-elicit` would immediately refuse.

## Notes

- **Delegate elicitation, never duplicate it.** Interactive questioning belongs exclusively to `cadence-elicit`. This triage skill merely checks whether to *offer* the interview (Medium/High tier with >0 unanswered probes), while `cadence-elicit` enforces all capture and rubric rules under `docs/policies/change-tiers.md`.
- **Why the offer lives in the skill rather than the subagent.** Conducting an interview requires live turn-by-turn user input. Subagents run headlessly without interactive user prompts, so the interview offer must execute in the top-level skill turn after `cadence-triage-agent` returns.
- **Identifier numbering authority resides in the §10 binding.** For description-first tickets, step 2 allocates the identifier *prior* to subagent delegation: either reserving a key from the bound tracker when an allocator is configured, or minting via the local atomic sequence sidecar when unbound. The governing contract — mint-by-convention vs. reserve-from-tracker, allocator contingency, and the subagent's use-verbatim / never-mint rule — lives in `CADENCE_ORG.md` §10 *Id Allocation Binding* (with vendor-specific reservation scripts residing in the bound tracker's `/sync-*` skill directory).

## Handoff mode (decomposition children)

This contract governs cross-skill decomposition between `/cadence-elicit` (step 4d) and `/cadence-triage`. For each proposed child ticket, `/cadence-elicit` invokes `/cadence-triage` with the following handoff payload:

| Field | Req | Meaning |
|---|---|---|
| `problem_description` | yes | Child ticket's boundary statement and standalone success criterion |
| `parent_ticket_id` | yes | Recorded in the child's `metadata.yaml` under `decomposed_from:` |
| `proposed_tier_hint` | no | Initial tier suggestion; triage may adjust based on the child's own scope evidence |
| `suppress_elicit_offer` | yes | `true` — suppresses step 5 so the child does not recursively trigger `/cadence-elicit` |
| `propagated_answers` | no | Verbatim parent Q&A blocks copied into the child with `**Source:** propagated-from-parent` |
| `idempotency_key` | yes | Opaque 12-character lowercase hex digest stored on the child for crash-safe duplicate detection |
| `sequencing_rationale` | no | Included only when the size/sequencing split-test exception was invoked |

Return payload (one object per child, returned to `cadence-elicit`):

| Field | Meaning |
|---|---|
| `child_ticket_id` | Newly allocated child id (or existing child id when `status: duplicate`) |
| `status` | `created` \| `duplicate` \| `refused` (e.g., rejected by a `PROJECT_INTENT` scope check) |
| `scope_check_result` | Outcome of the project-intent alignment check for this child |
| `idempotency_echo` | Echoed `idempotency_key` allowing `cadence-elicit` to verify pairing integrity |

`cadence-elicit` enforces **all-or-nothing transactionality**: if any child call returns `refused` or errors out, `cadence-elicit` deletes all children with `status: created` from the current run and leaves the parent's `decomposed_into:` unset. `/cadence-triage` itself only creates (or detects a duplicate of) one child per invocation and never mutates parent lineage.

## Example

```
/cadence-triage TT-6547
```

Classifies ticket `TT-6547`. When the resulting tier is Medium or High and `problem.md` has unanswered probes, prompts the user to walk through them immediately; on `yes`, runs `/cadence-elicit` in the same turn and writes the `## Elicited Intent` section to `problem.md`.

```
/cadence-triage "checkout total ignores expired coupons"
```

Mints an identifier and triages a free-text problem statement directly. Tickets classified as Trivial or Low bypass the probe interview offer.
