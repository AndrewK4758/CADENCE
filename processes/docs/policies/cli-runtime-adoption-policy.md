# CLI Runtime Adoption Policy (`.agents/` Primary + `.gemini/` Reference Implementation)

**Status:** Canonical Governance Policy  
**Applies to:** All CADENCE-governed repositories, `/cadence-adopt`, `/cadence-upgrade`, and `import/link-sdlc.sh`

---

## 1. Core Architectural Principle

Every modern agentic CLI tool supports or can project from `.agents/`. To eliminate vendor lock-in and prevent duplicated definitions across tool-specific hidden directories, CADENCE establishes a strict **two-layer runtime model**:

1. **`.agents/` is the Universal Primary Source of Truth** in every repository:
   - `.agents/agents/<role>/agent.md` — Canonical agent definitions
   - `.agents/skills/<skill>/SKILL.md` — Canonical skill workflows and helper scripts
   - `.agents/hooks/` — Canonical lifecycle hook scripts and `hooks.json`
   - `.agents/agents.json` & `.agents/skills.json` — Declarative discovery manifests
   - `AGENTS.md` (at repo root) — Universal entry-point instructions importing `CADENCE_DIRECTIVES.md`

2. **`.gemini/` is the Canonical Reference Implementation** for Google Antigravity (`agy`) and Gemini CLI:
   - `.gemini/` derives 100% of its agents, skills, and hooks directly from `.agents/` via symlinks or declarative `agents.json` / `skills.json` pointers.
   - Any other CLI runtime (such as Claude Code `.claude/`, OpenCode `.opencode/`, or Cursor `.cursor/`) **must project its runtime directory off `.agents/`**, modeling its adapter after the `.gemini/` reference implementation rather than maintaining independent copies.

## 3. Reference Implementation Specification: `.gemini/` (Antigravity / `agy`)

The `.gemini/` adapter (`ci-templates/scripts/adapters/gemini-agy.sh` and `import/link-sdlc.sh`) is the benchmark against which all other CLI adapters are modeled:

1. **Frontmatter Contract (`agent.md`)**:
   - `model:` uses validated tier aliases (`pro` for Gemini 4 Argon deep reasoning; `flash` for Gemini 3.8 Flash high-breadth mechanical work) with `# Tier:` comments documenting the exact model mapping from `CADENCE_ORG.md#model-tier-mapping`.
   - `subagent: true`, `enable_mcp_tools: true`, and `inheritMcp: true` are set so every CADENCE subagent automatically inherits the `local-offload` MCP server (`offload_log_triage`, `local_semantic_embed`, `offload_deep_review`) and bound tracker MCP servers (`youtrack` / `jira`).
   - Read-only roles (`cadence-architect`, `cadence-reviewer`, `log-triage`, `repo-scout`) enforce `enable_write_tools: false`.
   - System prompt bodies begin immediately with an `# H1` heading after the closing `---` YAML frontmatter delimiter.
2. **Hook Projection (`hooks.json`)**:
   - Links `.gemini/hooks.json` (or global `~/.gemini/config/hooks.json`) to `.agents/hooks/hooks.json`.
   - Executes `local-offload-enforcer.sh` (`PostToolUse` on command execution), `tms-sync-reminder.sh` (`PostToolUse` on file edits), and `tms-doc-sync-stop.sh` (`Stop` at turn completion).
3. **Instruction Inheritance (`GEMINI.md`)**:
   - Contains a thin managed header importing `AGENTS.md` and `CADENCE_DIRECTIVES.md` so project-specific rules live in one place (`AGENTS.md`).

## 4. Adapter Rules for Secondary CLI Tools (`.claude/`, `.opencode/`, etc.)

When a contributor or team uses another CLI tool alongside or instead of `agy`, they must **never fork or copy files out of `.agents/`**. Instead, they run `import/link-sdlc.sh --claude <repo>` (or `/cadence-adopt` with the target runtime specified in `CADENCE_ORG.md#runtime-binding`), which applies the following projection rules modeled after `.gemini/`:

| CLI Runtime | Directory Projected Off `.agents/` | Instruction Entrypoint | Adapter Script |
| :--- | :--- | :--- | :--- |
| **Antigravity / Gemini CLI (Reference)** | `.gemini/agents -> ../.agents/agents`<br>`.gemini/skills -> ../.agents/skills`<br>`.gemini/hooks.json -> ../.agents/hooks/hooks.json` | `AGENTS.md` + `.gemini/GEMINI.md` | `ci-templates/scripts/adapters/gemini-agy.sh` |
| **Claude Code** | `.claude/agents -> ../.agents/agents`<br>`.claude/skills -> ../.agents/skills`<br>`.claude/hooks -> ../.agents/hooks` | `AGENTS.md` + `CLAUDE.md` | `ci-templates/scripts/adapters/claude-code.sh` |
| **OpenCode** | `.opencode/agent -> ../.agents/agents`<br>`.opencode/command -> ../.agents/skills` | `AGENTS.md` | `ci-templates/scripts/adapters/opencode.sh` |
| **Blitz** | `~/.blitz/agents/<role>.md -> .agents/agents/<role>/agent.md`<br>`~/.blitz/skills/<skill> -> .agents/skills/<skill>` | `AGENTS.md` + `~/.blitz/.env.toml` | `ci-templates/scripts/adapters/blitz.sh` |

### Mandatory Invariants for All CLI Adapters
1. **Single Source of Truth (Behavior 6):** Editing an agent, skill, or hook inside `.claude/` or `.gemini/` is forbidden if it breaks the symlink to `.agents/`. All edits happen in `.agents/` (or in `/home/ak/projects/sdlc` when linked globally) so every CLI runtime observes the exact same governance behavior immediately.
2. **Automatic Local Offload Parity:** Every CLI adapter must wire the `local-offload` MCP server (`/home/ak/.local/bin/antigravity-local-offload-mcp`) and the `.agents/hooks/local-offload-enforcer.sh` hook so Tier 1 CPU (`:11434`) and Tier 2 Hybrid/GPU (`:11434`) offloading occur automatically regardless of which CLI binary invokes the skill.
3. **Dual-Payload Hook Compatibility:** All scripts in `.agents/hooks/` parse both Antigravity JSON payloads (`toolCall`, `workspacePaths`, `terminationReason`) and Claude Code / generic JSON payloads (`tool_input`, `cwd`, `session_id`) so a single hook script in `.agents/hooks/` serves every CLI runtime without modification.
